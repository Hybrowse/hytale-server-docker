Persistence:
{{- if .Values.persistence.enabled }}
  Keep /data: it contains worlds, server files, encrypted login and machine identity.
  New claims default to 20Gi. Allow more space for worlds, mods, backups and native updates.
  Changing persistence.size does not resize an existing StatefulSet claim automatically.
{{- else }}
  WARNING: /data uses emptyDir. Pod replacement loses worlds, files and login credentials.
{{- end }}

First startup:
  Set env.HYTALE_AUTO_DOWNLOAD=true to download missing files, or provision them first.
  Follow downloader and automatic server login prompts in: kubectl logs -f <pod>
  Select a profile: kubectl exec <pod> -- hytale-cli auth select <name-or-number>
  Existing stored credentials, supplied tokens and broker auth skip automatic server login.

ARM64:
  Downloads work on AMD64 and ARM64; only the official downloader is emulated on ARM64.
  Java stays native. No privileged mode or architecture node selector is required.

Probes and updates:
  probes.enabled=true enables readiness by default without a startup or liveness timeout.
  Readiness checks process/files/UDP, not successful account authentication.
  Native updates are opt-in. Keep a PVC, backups and enough disk space; see the guide.

Configuration and secrets:
  Use .Values.env for image settings; HYTALE_BIND defaults to 0.0.0.0:{{ .Values.service.port }}.
  .Values.secrets supports server tokens, CurseForge API keys and downloader credentials.
  Guide: https://github.com/Hybrowse/hytale-server-docker/blob/main/docs/image/kubernetes.md
